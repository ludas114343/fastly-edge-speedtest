# TaskCard: taskcards/phase4/redteam-agent.md

## 1. 背景
Red Team 专职采取黑客与对抗视角，专证是否存在任何虚构、套壳或造假。

## 2. 唯一目标
专证以下 10 个致命漏洞：
1. 6000 条是否只是候选而非节点？
2. Fastly 实际是否回源 CF/Supabase？
3. EdgeOne 实际是否未部署四层出站？
4. Netlify 是否只是静态页面或订阅分发？
5. Northflank 是否把 1 个部署复制成 34 次？
6. Wasmer 节点是否通过改名制造多国？
7. CF/AWS 入口出口标签是否混淆？
8. 用户系统代理或注册表是否被任何脚本修改？
9. 订阅链接是否存在且有效？
10. 结果 JSON 是否能够从 raw JSONL 100% 完整复算？

## 3. 输入路径
- 全库产出物、历史日志与订阅文件

## 4. 允许操作
- 深入源码与日志做对抗性质询
- 编写红蓝对抗专审报告

## 5. 禁止操作
- 严禁对发现的漏洞打掩护
- 严禁在英文注释或文档中使用 em-dash (\u2014) 与 en-dash (\u2013)

## 6. 必须执行的命令或 API
- 对抗性审查脚本与数据校验命令

## 7. 必须生成的文件
- `docs/security/redteam_v12.md`

## 8. 机器可判定验收条件
- 逐一回答上述 10 项质询，附硬核证据并给出 PASS / FAIL / BLOCKED 结论

## 9. 停止条件
报告落盘后停止。
